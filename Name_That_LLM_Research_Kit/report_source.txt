# Name That LLM: independent research and experiment plan
Research cutoff: 2 November 2026
Scope: passive attribution of a single passage to one of 18 exact competition labels.
Status: read-only data analysis and research completed. No attribution model was trained, no source model was queried for new examples, and no predictions were submitted.

## A. Executive recommendation

The best-supported starting strategy is a style-preserving, direct 18-class classifier, evaluated against a strong character/word baseline on unseen prompt groups. The likely final candidate is a small ensemble of genuinely complementary branches: a fine-tuned encoder; raw character/word features; and, only if it adds held-out value, frozen proxy-model likelihood or hidden-state features. This is a ranked hypothesis, not a claim that an untested ensemble is already the winner.

Begin with regularized TF-IDF classifiers and a compact stylometric model. Compare a modern 150M-400M encoder and a contrasting older encoder under the same splits and tuning budget. Test cross-entropy (CE) before adding supervised contrastive learning (SupCon). The cleanest advanced experiment is CE versus CE+SupCon on the same backbone, using same-model/different-prompt positives and same-prompt/different-model negatives. A source-conditioned generative model inspired by ATLAS is the highest-upside alternative mechanism, but its published family-attribution results do not establish exact-version superiority here. [R04-R10, R14-R16]

The actual corpus changes the priorities. All 2,699 training passages are single-line prose. Typography differs sharply across providers, and lexical word length and punctuation retain substantial model association after an additive prompt/length adjustment. Yet adjacent versions still share many family signatures. Preserve raw Unicode and punctuation; do not make generic normalization or paraphrase augmentation the default. Data collection should emphasize short science/humanities explanations, reflective prose and evocative descriptions, not a broad instruction-tuning mixture of emails, recipes and code.

The most urgent external-data issue is source identity. Google documents that gemini-3.7-flash requests now route to gemini-3.8-flash. GPT-5.5 has left ChatGPT but remains documented in the API. Several other targets are documented API models without verified current consumer-chat selection. Seventeen nominal target endpoints have official API documentation, but equality with the competition's historical checkpoint and serving conditions remains unverified. A generic provider name or a model's self-description is insufficient provenance. [R17-R25, R33]

Do not prioritize reinforcement learning. Passive classification has no query-action loop. For choosing collection prompts, first compare a fixed matched panel and simple error-driven acquisition. RL would need to beat these on downstream balanced accuracy at equal collection cost, not merely identify an interactively queried model. [R11-R13]

The leading recommendation would be falsified if the lexical baseline consistently wins on new prompts, a generative method improves exact-version recall across the same splits, or a frozen feature model achieves comparable accuracy with less variance and runtime. No defensible private-leaderboard score forecast can be made before those experiments.

## B. Dataset findings and what they imply

### B1. Verified structure and limits of verification

The supplied train.csv has 2,699 rows and columns id, prompt_id, text, model. It contains 150 distinct prompt groups and exactly the 18 labels in the request. There are 149 complete groups of 18; p002 lacks claude-fable-5. Every other class has 150 examples and that class has 149. There are no empty fields, duplicate IDs, or repeated prompt/model cells. The original files were read in full programmatically and left unchanged. The kit records SHA-256 hashes. [D1]

The supplied test.csv contains three example rows and columns id, text. The supplied Parquet sample contains the same three IDs and string-valued id/model columns. It is a format demonstration, not the hidden test. Official pages specify approximately 4,000 hidden passages from unseen prompts, balanced accuracy, unequal class frequencies and different public/private mixtures. The overview says one interactive example while the data page says three; the supplied file resolves that minor documentation discrepancy. The hidden test has no documented prompt_id column. [D1, R01-R02]

### B2. Length, sentence and formatting measurements

Whitespace-delimited word counts range from 36 to 274, with median 101, mean 114.66 and 95th percentile 224. There are 41 passages outside the advertised approximate 40-250-word interval. These are not grounds to delete records. Using o200k_base as a common token-count probe gives median 128, mean 145.34, 95th percentile 280.1 and maximum 376. This is neither the original source tokenizer nor a guarantee that every encoder fits a 384-token cap; audit each candidate tokenizer separately. [D1]

Every passage has one line, no tabs, no leading/trailing whitespace and no runs of multiple spaces. The implemented checks find no headings, bold markup, line-start bullet/numbered lists, code fences or URLs. Five passages match a LaTeX-marker heuristic, fifteen contain an asterisk, and twelve change under NFKC normalization. Sentence-boundary heuristics give a median of five, with a 0-14 range; the zero count denotes missing terminal punctuation rather than absence of linguistic sentences. [D1]

These observations support short sequence lengths and dynamic padding. They do not establish whether a shared prompt template, provider behavior, or organizer cleanup produced the plain paragraphs. Keep one raw-text path; use alternate normalization only as a controlled ablation. Drop zero-variance numeric features within training folds. General chat lists and code blocks should be a small, separately identified collection arm.

### B4. Controlling for prompt and length

For each numerical style feature, I projected out prompt indicators and a quadratic function of log(1+word count), then measured the additional variance explained by family or exact-model indicators. These are descriptive fixed-effects decompositions, not an attribution classifier. Exact-model indicators explain 43.52% of the remaining variation in mean lexical word length, 40.68% in em-dash density, 20.99% in colon density and 14.06% in semicolon density. Adding version indicators beyond family explains 24.62% of the remaining lexical-word-length variation but only 2.85% of the remaining em-dash-density variation. [D1]

This is evidence that class-associated differences are not simply the result of different prompts being assigned to different models. It does not prove generalization, causality, independence of all topic effects, or immunity to nonlinear length effects. The lexical regex splits accented words; sentence counts are heuristic. Added model parameters mechanically improve in-sample fit, with a simple null scale around 0.0067, so tiny positive effects should not be celebrated. Prompt-block permutations or held-out feature associations would be the next inferential checks. No feature R-squared here is balanced accuracy.

Overall response length is a much weaker clue: after accounting for prompt, model identity explains about 1.05% of residual word-count variance. Length should be available as a weak feature and diagnostic, not a routing rule. Do not condition away all length information during normal training merely because length was controlled in this audit. [D1]

### B5. Lexical signals, topics and duplicates

An exploratory binary phrase-frequency audit required at least six occurrences for the target model and at least six prompt groups overall. Examples include "an intricate" in 10 Gemini 3.7 responses versus five responses from all other classes combined; "all of it" in six Opus 5 responses versus four elsewhere; and "is therefore" in seven Luna responses versus 22 elsewhere. These small, multiply searched counts are feature hypotheses, not hand-written identification rules. Avoid a blacklist of supposedly diagnostic words. [D1]

Manual semantic annotation inspected a representative beginning/ending from every prompt group, a GPT-5.5 excerpt from every group, and extra excerpts for ambiguous narrative groups. All inspected excerpts were predominantly English. This is not a language-detector result over every row. The inferred domain counts below describe response content, not original prompts. [D2]

The inferred primary genres were evocative exposition 63 groups, conceptual explanation 38, reflective argument 36 and creative scene 13. ### B6. Preprocessing and misleading shortcuts

ASCII-only filtering changes 1,561 passages; folding smart quotes/dashes changes 1,529; lowercasing changes all 2,699. Stripping or collapsing whitespace changes none in this release. Preserve the original string and explicit transform versions. The absence of current whitespace variation does not justify losing future paragraph boundaries during external collection. Scikit-learn's built-in character analyzer internally collapses repeated whitespace even with lowercase=False; use a custom raw-character/byte analyzer or explicit whitespace features when byte fidelity matters. [D1, R28]

Exclude id, row order and prompt_id from prediction features. Do not infer test prompts and enforce one example per model per cluster. The training crossing does not establish the same hidden-test structure. A participant reports that Hungarian matching improved local validation but failed to improve the public score; this is unverified competition anecdote, consistent with the official warning about unequal class mixtures, not proof of the hidden construction. [R01, R31]

### C1. What the relevant studies actually show

Every Model Leaves a Trace (20 October 2026 preprint) is unusually relevant because it uses prompt-grouped evaluation and tests related sources. Its eight-way raw-text experiment reports 80.07% accuracy for lexical logistic regression, 66.04% for semantic features and 81.41% for combined features. These are its own models, prompts and class resolution. Its strongest prompt-neutralized embedding diagnostic needs peer responses from every candidate to the same test prompt; that is not available here. Its original semantic branch uses an online OpenAI embedding model. Treat the lexical result as a reason to test simple methods, not an expected Kaggle score. [R04]

OpenTuringBench (EMNLP 2025) provides a Longformer/triplet/centroid framework and a public benchmark. OTBDetector's weighted F1 changes from 0.997 in-domain to 0.510 on out-of-domain essays in its attribution tables. The benchmark uses much longer texts, older open generators and a human class. Contrastive learning can work very well within a distribution while still failing under a meaningful shift. Its dataset card is CC BY-NC 4.0; studying the method does not automatically make the data eligible for unrestricted reuse. [R06, R38]

Profiler (EMNLP 2025) extracts context-aware loss patterns from frozen surrogate LMs and trains random forests. Its evaluation is predominantly one-versus-rest origin detection with ROC-AUC; its OOD cases include paraphrasing rather than this exact unseen-prompt test. The official implementation is available. It is a plausible complementary feature generator, but a high AUC does not establish that scores from eighteen separate binary detectors are comparable or yield high balanced top-1 accuracy. Refit/evaluate a multiclass decision rule. [R05, R35]

READER (2026 preprint, verified v3) summarizes frozen proxy hidden-state trajectories with low-frequency coefficients and can accumulate evidence across interactions. On its 100-source, 500-prompt Agent500 experiment, one-response READER-Qwen accuracy is 50.4%; a fine-tuned Qwen3-Embedding-8B baseline reaches 55.4% in the appendix. Its 96.2% result combines 100 responses from the same source and is not the relevant endpoint. Use response-only K=1 features and compare against adapted embeddings. Published timing uses H200 hardware and caching, so it cannot be reused as an L40S estimate. [R07, R37]

ATLAS (14 October 2026 preprint) uses a frozen Qwen2.5-7B model with shared/source-specific low-rank parameters and clipped relative token-likelihood aggregation. Its headline joint domain/version-shift accuracy is 74.27% versus 65.27% for its strongest baseline, on five-family identification with 149,760 machine-generated training texts. Its objective preserves family identity across versions; this task separates versions. An eighteen-source adaptation with far less data is therefore a novel experiment. Code exists; the reported full experiment uses four H100-80GB GPUs, which does not establish a required configuration for this smaller adaptation. [R08, R36]

SemEval-2024 Task 8 supplies useful competitive evidence: AISPACE's encoder ensemble ranked first in six-way generator/human attribution at 90.85% accuracy. A different CE+contrastive system did not dominate the shared task. In that system's enriched PeerRead experiment, synonym replacement and random word swaps changed accuracy from 74.60% to 58.81%. These incompatible tasks are not compared as a league table; they motivate supervised baselines and caution against source-changing augmentation. [R09-R10]

Ettin (ICLR 2026) and the October 2026 UltraBERT release are contemporary encoder candidates with public checkpoints. Their general classification evidence does not establish LLM-attribution superiority. Test one of them alongside a contrasting proven architecture instead of automatically selecting the newest or largest encoder. New sparse lexical authorship work also merits an optional later comparison, but its human-authorship task is indirect evidence. [R14-R15, R29]

Fingerprinting LLMs via Prompt Injection (ACL 2026, LLMPrint) optimizes prompts for provenance/derivation verification, including many post-trained variants. LLMmap (USENIX Security 2025) actively queries a model; its greater-than-95% result over 42 versions uses eight chosen interactions. Both require access to the unknown authoring model. Kaggle provides a fixed passage, so these results cannot be imported as passive-attribution evidence. [R11-R12]

### C2. RL, active collection, provenance and watermarking

The four settings must remain distinct. Passive attribution maps an existing passage to a label. Active identification chooses inputs for an unknown model. Active collection chooses independent prompts for already known source models. Adaptive allocation decides which source/prompt cells to purchase next. Only the latter two are available during this project's data collection; the first is the submission task.

One RL fingerprinting preprint reports 93.89% accuracy from three selected queries versus 82.22% from three random queries, over nine open models and a fixed 50-query pool. This does not show an advantage over greedy information gain or Bayesian experimental design, and it does not optimize downstream passive-classifier accuracy. Start with stratified matched sampling, pair-confusion counts, uncertainty/disagreement on newly generated candidate responses and an explicit held-out reward. [R13]

Information gain about a queried source is not the same objective as expected improvement on naturally distributed test passages. Use diagnostic distinctiveness as an acquisition heuristic, then accept prompts only if their generated data improve target-like held-out performance. A useful later policy could allocate among domain/length/pair arms using simple bandit-style allocation; RL is justified only if a sequential advantage survives equal-cost comparison with these simpler policies.

Watermarks require an applicable generation mechanism and a usable detector or key. Google documents text watermarking in Gemini experiences, but neither the supplied data nor retrieved competition documentation establishes a detector/key for all target passages or exact-version payloads. Watermark-inspired statistical features may be tested if concrete evidence appears, but watermark decoding is not a defensible main plan. A provider-level provenance signal would still leave version attribution unresolved. [R30]

## D. Detailed architecture and training recommendation

### D1. Baseline system and preprocessing

Use only the passage string at inference. Keep its raw Unicode, case and punctuation. Construct three independently inspectable branches: raw-character TF-IDF; word TF-IDF; and roughly 20-60 nonconstant numeric style features. Start with character n-grams 3-5 and 2-6 as two alternatives; word unigrams/bigrams; min_df 2 or 3; sublinear TF as an ablation; and a small regularization grid C in {0.1, 1, 10}. These are proposed settings, not claimed optima. Compare multinomial logistic regression with a linear SVM. Fit vocabulary and IDF only on the training portion of each split.

Numeric features should include lexical length, length-adjusted vocabulary richness, punctuation densities, capitalization, contractions, pronoun rates and sentence-boundary patterns. The initial corpus offers little value for complex layout features because most are constant. A modest boosted-tree model is useful for nonlinear interactions; a linear style model remains a strong control. Historical Delta-style function-word distances, character Markov models and compression distances are inexpensive secondary baselines, with no verified contemporary exact-version advantage here.

Keep raw and lightly normalized views as separate experiments. Do not paraphrase passages with another LLM, translate them, swap synonyms or automatically correct grammar while retaining the original model label. These operations can transfer or erase the source signature. Dropout-based representation regularization is safer to test because it does not rewrite the recorded source text.

### D2. Practical neural baseline

First compare three carefully bounded alternatives: a 150M-400M current encoder such as Ettin/UltraBERT; a contrasting DeBERTa-v3 or RoBERTa architecture; and a frozen open embedding model with a regularized head. Then spend compute only on surviving backbones. Qwen3-Embedding-8B with LoRA is a larger challenger supported by relevant single-response evidence; it is not the mandatory starting point. [R07, R14-R16]

Proposed initial recipe: exact 18-way CE, AdamW, BF16 on L40S, learning rate 1e-5 or 3e-5, weight decay 0.01, effective batch 32-64, 5-10% warmup and a short schedule of 3-10 epochs selected using inner validation. Audit candidate-tokenizer lengths, initially cap at 512 only if the audit supports it, and use dynamic padding. Compare the architecture's recommended pooled representation with mean pooling in one bounded ablation. Preserve all eighteen logits. With the official 150/149 counts, large class weights or aggressive oversampling are unwarranted.

Use full fine-tuning for compact encoders; parameter-efficient tuning is not inherently more accurate. For an 8B challenger, begin with LoRA rank 8 or 16, learning rate 5e-5 to 2e-4, microbatch 2-8, accumulated batch 32-64 and gradient checkpointing. Use BF16 base weights if memory allows, or QLoRA NF4 with BF16 computation. Exact memory and speed require a pilot. A classification head avoids decoding long label explanations. For a generative head, prefer fixed-length class codes, verified against its tokenizer; otherwise compare sum-log-probability and length-normalized label scores inside inner folds. Length normalization is an ablation, not an automatic correction. [R27]

### D3. Controlled contrastive and hierarchy experiments

Compare CE with CE + lambda*SupCon, initially lambda in {0.05, 0.2}, on otherwise identical configurations. A true contrastive batch can contain two or three complete prompt groups, giving 36 or 54 texts. Same exact model across prompts provides positives; other models answering the same prompt provide topic-controlled negatives. The missing Fable cell is naturally omitted. Harder same-family negatives can be emphasized only after plain CE errors have identified stable confusion pairs.

Ordinary gradient accumulation does not enlarge the contrastive denominator. Embeddings must coexist through an actual batch, gradient caching, or a carefully documented queue. Test linear-head prediction and prototype/centroid prediction separately. Do not force all provider siblings into one tight embedding cluster when they are distinct labels.

A family auxiliary head is an ablation, not the default. Its loss must not overwhelm the exact-label objective. Soft factorization p(model|text)=p(family|text)*p(model|family,text) is worth testing against direct CE; hard routing permanently converts an early family mistake into an exact-label error. For a specialist pair, preserve or renormalize the pair's total probability mass and evaluate the full 18-class outcome. Oracle-family or pair-only accuracy is a diagnostic, not the competition objective.

### D4. Complementary and generative candidates

Start with one frozen local causal model. Cache response-only hidden-state summaries from a small preregistered set of layers and/or token/context likelihood features. Fit standardization, feature selection and classifier parameters inside each fold. All candidate training text can be passed through an entirely frozen feature extractor without fitting it, but no validation information may influence layer selection or learned normalization. Profiler-style context losses can require more work than one ordinary perplexity pass; measure the actual implementation. [R05, R07]

For ATLAS, use an eighteen-condition source adapter with shared parameters and stronger regularization than a large-data recipe might need. Train only on the current outer-training sources. Compare ordinary normalized log likelihood against clipped relative token evidence. The eighteen exact labels must remain separate. A smaller 1B-3B implementation may be a feasibility prototype, but changing the backbone/objective is an adaptation, not reproduction of the published result. Run a 7B comparison only if the cheap prototype shows meaningful evidence. [R08]

Direct source-model perplexity would require comparable scoring access to every exact historical generator. That access is not established, the sources are generally not portable to the submission notebook, and runtime API calls are forbidden. A proxy likelihood is a learned surrogate measurement, not the source model's true probability. Do not treat whichever proxy gives the lowest perplexity as the author without a trained, validated attribution rule.

### D5. Ensembles, calibration and distillation

Measure per-class error overlap and how often each branch corrects the current leader. An oracle union of correct predictions is only an upper bound on possible complementarity. Test the actual probability or logit blend on outer-held-out prompts, using global weights first. Class-specific weights and offsets have many parameters relative to 150 groups; use strong shrinkage and inner-fold fitting if tried.

Positive scalar temperature scaling does not change a single classifier's argmax and therefore cannot by itself improve its balanced accuracy. It can help a mixture combine differently scaled confidences. Fit calibration inside training folds. Under stable class-conditional distributions, the balanced-accuracy Bayes rule is argmax_k p(text|k), equivalently argmax_k p_train(k|text)/pi_train(k). The near-uniform original prior needs almost no adjustment. Unknown test priors do not justify forcing equal output counts or ordinary accuracy-oriented prior correction.

After a teacher ensemble has demonstrated a gain, distill it into a compact classifier using hard labels plus temperature-scaled soft targets. For each outer fold, the teacher must be trained without its validation passages; its architecture, mixture and calibration must also be chosen without them. A teacher may produce targets for permitted external examples offline, but source model labels remain the generation provenance, not a teacher's guess. Compare the distilled student with the same student's hard-label training and the teacher's actual deployed accuracy/runtime.

Pseudo-labeling is low priority. The three preview examples offer no meaningful self-training pool. Before relying on any adaptation to hidden text during rerun, verify eligibility under the rules and organizer clarifications; no blanket prohibition on all automated transductive methods was established here. Do not export hidden text or hand-label it. A later eligible self-training experiment should use automatic labels, high-confidence agreement, low weights and an analogous untouched-prompt simulation; abandon it if it reinforces sibling confusion.

## E. External-data prompt engineering package

### E1. Strategy: matched natural prose first, diagnostic prompts as a separate arm

Use a diverse prompt bank with a shared prompt for every accessible exact nominal source. A universal content prompt produces too few independent situations. An oversized generic chat bank mismatches the observed domain. A bespoke prompt for each model confounds author with content. A crossed panel preserves comparisons and supports topic-controlled negatives. Different prompts may be used for a confusing pair only when both members receive the same new prompts, with periodic full-panel anchors.

The initial bank contains 24 independently authored training prompts, six untouched external-evaluation prompts and six diagnostic prompts. The 24 core prompts span four requested length bands evenly: 40-70, 90-130, 160-210 and 220-250 words. Their domain/genre mix is broad within the observed science/humanities setting; it is not claimed to be the optimal hidden-test mixture. Longer expansion should approximate the observed empirical length distribution or reweight/stratify length, rather than assuming these four equal bands match it exactly.

Most core prompts request one paragraph but leave wording, sentence structure, punctuation and argument development free. That is a distribution-matching hypothesis based on the actual file, not a recovered organizer instruction. Diagnostic D01 and D05 deliberately allow ordinary formatting freedom. After the first panel, compare several equivalent output wrappers on new independent topics, with wrapper choice crossed across all sources. Every paraphrase, length variant and repeated generation of the same conceptual request shares one prompt_family_id and one validation group.

Do not instruct models to reveal their identity, imitate another model, exaggerate a house style, use a distinctive catchphrase, or answer with a prescribed word list. Such prompts can be easy to identify for the wrong reason. Do not provide examples taken from the competition. Never paste hidden or official passages into unrelated chat services for labeling, rewriting or source guessing.

### E3. Manual operator workflow

1. Verify the source before collection. Record the exact displayed model, official model identifier where available, product, date, region and any selected effort/mode. A screenshot of the model selector or API response metadata can be retained privately as evidence; do not include account/payment details in shared artifacts. Model self-identification is not evidence.

2. Use a fresh conversation for every sample. Disable memory, personalization and custom instructions where the interface allows it. Record unknown settings as unknown. A temporary chat does not necessarily remove provider system instructions. Do not claim that consumer chat is equivalent to a bare API request.

3. Disable browsing, retrieval, connectors, file context, agent swarms and tool execution where possible. Do not use a research mode or multi-agent mode to represent one ordinary source. If an interface forces tools or hidden routing, label that condition and keep it out of the highest-trust core panel.

4. Use the same initial prompt across accessible sources. Rotate collection order across providers and dates so a topic or length is not tied to a particular model or service update. Prefer completing a small cross-model panel before collecting hundreds from a single model.

5. Collect the first complete answer, even if it is awkward, inaccurate, unexpectedly short, or ignores the word target. Record task compliance and actual length. Selecting the nicest or most diagnostic response introduces a collector-specific filter. Log genuine technical failures and retries instead of silently replacing samples.

6. Keep the final visible answer separate from any visible reasoning panel, tool trace or interface footer. Do not ask for hidden reasoning. If final-answer extraction is ambiguous, keep the raw export and mark the record for review rather than constructing a cleaner answer by hand.

7. Use the interface's copy/export facility consistently. Record whether copying preserves Markdown source, rendered text, newlines, Unicode and equations. Store the exact captured text and a SHA-256 hash. When underlying raw bytes are unavailable, call the field a captured raw response; it is not a byte-perfect server record. Preserve any alternate rendered export separately.

8. Do not edit spelling, punctuation, sentence count or factual mistakes. Do not strip a preamble or wrapper in the primary record. If testing organizer-like cleanup, create a derived field with an explicit transform version and retain the original. All derivatives stay with their parent validation group.

9. Keep the first response as the primary sample. Follow-up corrections, continuations and regenerations are separately labeled conditions, not independent fresh-prompt examples. Avoid dozens of repeated samples from one prompt: they increase rows much faster than independent prompt coverage.

10. Use UI defaults when controls are unavailable, recording them as unknown/default rather than inventing temperature values. Where exposed, hold settings fixed within a core arm; later compare a small preregistered range across all accessible models. Reasoning settings can change visible style and billing. Do not assume every model accepts temperature zero or can disable reasoning.

11. Review provenance and deduplicate exact captures before admission. Exclude provider navigation text, mixed-source stitched answers, accidental multi-turn history, confirmed fallback, and unknown-author imports from exact-label training. Preserve quarantined records and reasons so collection is auditable.

12. Obtain organizer clarification for conditional paid/private sources before relying on them. A source being technically reachable is distinct from competition eligibility. The owner performs collection; this research has made no generation requests or spending commitments.

### E6. Adaptive expansion and external-data falsification

The first collection stage is 24 core prompts across the 17 currently documented nominal targets: up to 408 training responses, plus 102 H-prompt external holdout responses if all are accessible. Six H prompts are only a gross-transfer sentinel: expand to approximately 30 or more new independent holdout families before interpreting model differences, and let confidence intervals determine whether more are needed. Reserve 20-25% of subsequent new prompt families for evaluation. The six D prompts add up to 102 diagnostic responses, but six independent prompt groups are a small pilot rather than a conclusive comparison. Missing cells stay missing. Do not inflate the corpus by mapping current 3.8 responses to unavailable 3.7.

Expand only after a provenance-controlled pilot. A reasonable next scale is 50-100 independent training prompts per accessible target, or roughly 850-1,700 responses. If learning curves continue improving, test 150-500 prompts/model, roughly 2,550-8,500 responses for seventeen sources. These are suggested experiment sizes with substantial uncertainty, not sample-complexity guarantees. The unit worth expanding is independent prompt coverage, not raw response count.

Audit existing public synthetic corpora before spending large amounts of operator time. One Kaggle dataset description reports 7,753 passages across ten target names, a CC BY 4.0 license, mixed OpenRouter/OpenAI routes, some missing served-model metadata and filters for single-paragraph, non-Markdown text. I examined its description, not its underlying rows. Its 3.7 Flash records require particular date/route scrutiny; do not assume that a public label proves the served historical model or host approval. Public corpora may also share prompt sources with one another, requiring cross-corpus grouping. [R32]

Run at least three data conditions on the same held-out official prompt groups: official-only; external-only; and combined. Because one class is inaccessible for new collection, external-only is a 17-source diagnostic and cannot replace the official 18-class score. For a matched comparison, train and evaluate all three conditions on the same seventeen-label task, excluding 3.7 consistently. Separately report the full eighteen-class official-only and combined results with the original 3.7 examples retained. Never conceal the missing source or compare a seventeen-class headline directly with an eighteen-class score.

For combined training, choose a class uniformly, then select official versus external examples with an inner-tuned mixing weight, initially retaining at least half of exposure from official data. Fall back to official examples for missing external classes. Compare this mixed schedule with external pretraining followed by official-only fine-tuning. Balance domain/length within source where possible. Uniform class sampling does not remove the remaining class-by-corpus confound; specifically watch 3.7 recall and within-Gemini errors.

Compare naturalistic versus diagnostic augmentation at equal response count and comparable independent prompt count. The first six D prompts only test feasibility; expand the diagnostic bank with independent topics before claiming an acquisition advantage. Evaluate both arms on naturalistic official holdouts and H prompts, not only their own diagnostic examples. If diagnostic data only help diagnostic validation, do not scale that arm.

After the first models, prioritize weaknesses supported across inner folds: persistent sibling confusions; short passages; domains with low per-class recall; underrepresented lexical patterns; and collection-interface shifts. Acquire matched responses from both members of each selected pair. Keep some broad anchor prompts to detect unintended regressions. Avoid selecting every next prompt from one model's confidence score; combine disagreement, error prevalence and diversity. Bootstrap uncertainty and minimum sample counts should temper decisions from sparse slices.

Adaptive acquisition must respect the outer split as well. For an unbiased outer evaluation, each fold's selected prompts/data must depend only on that fold's training groups; do not pool acquisition decisions from all folds into a shared corpus, because a held-out group in one fold appears in another fold's training data. A simpler practical alternative freezes a shared, independently designed external panel before cross-validation. Subsequent global error-driven acquisition rounds are explicitly selection-affected development; assess the completely frozen recipe once on the locked confirmation set or a newly collected independent evaluation panel.

Externally generated data can reduce accuracy through mislabeled versions, new system prompts, UI-specific markup, temporal drift, selection filters or domain mismatch. If external-only transfer is poor, first examine these confounds. If combined training degrades the official score across repeated splits, reduce its weight, restrict it to an auxiliary objective, use an official-only final stage, or discard it. Extra rows are not inherently useful.

## F. Validation protocol

### F1. Primary research design and exact split sizes

Reserve 30 of the 150 official prompt groups as a one-time post-EDA confirmation set before any model experimentation. A reproducible implementation can sort prompt IDs by SHA-256 of the string "name-that-llm-confirm-v1|" plus prompt_id, then take the first 30. Save the manifest and prohibit reading its model errors during development. All 150 groups have already informed descriptive forensics, feature hypotheses and prompt-bank design; this is not a pristine untouched test. The lock prevents subsequent model selection, calibration and error-driven collection from using those groups. All eighteen labels are represented approximately equally because each prompt is a crossed panel.

Use the remaining 120 groups for primary development. Deterministically shuffle groups with a recorded seed, then allocate five outer folds of 24 groups. Each outer fit has 96 training groups, approximately 1,728 rows, and 24 validation groups, approximately 432 rows. Within its 96 training groups, use three inner folds of 32 groups for hyperparameters, early stopping, external-data weights, layer selection, calibration, specialist gates and ensemble weights. The one missing Fable row can reduce one count by one.

For each outer fold, choose settings only from inner results, refit on its 96 training groups, and predict the untouched 24 groups. Concatenate outer predictions over all 120 development groups and report balanced accuracy. Store every prediction, label order, fold manifest, configuration, seed, source revision and data hash. Do not call a meta-model unbiased merely because its input is OOF: fitting and evaluating its weights on the same OOF labels still overfits.

After ranking a small preregistered finalist set, repeat development evaluation with a second group partition and two model-initialization seeds where feasible. Partition seeds and initialization seeds measure different variation. Freeze the final recipe, fit on all 120 development groups and evaluate the 30 locked groups once. Do not repeatedly change the method after reading that result while continuing to call it a holdout. A failure should be recorded and may require a newly collected independent evaluation panel or an explicitly labeled new exploratory phase.

Once the recipe is chosen, all 150 official groups may be used for final fitting. Five-fold models trained over all 150 groups can be used for the final ensemble, or a full-data refit can use an inner-selected epoch budget. If all-150 cross-validation is additionally reported for comparison with community results, label it selection-affected rather than a second untouched confirmation. The externally generated H panel is independent by prompt but is also a distinct interface/time distribution, so it complements rather than replaces official validation.

### F2. Leakage controls

All outputs from the same prompt, all variants/paraphrases, repeated generations, derived crops/normalizations and teacher-generated descendants stay in the same group. Deduplicate before splitting and union genuinely duplicated prompt families. Fit vectorizers, feature selection, scalers, PCA, pooling/layer choices, adapters, hard-negative mining, calibration and blend weights without outer validation labels. A frozen pretrained tokenizer or fixed feature extractor is reusable; learned corpus statistics are not.

Only official training prompts may inform broad domain summaries. Actual original prompt text is absent, so prompt-template leakage cannot be completely excluded. Run a sensitivity split joining very close topical pairs identified by independent semantic audit. Then perform leave-domain-out or leave-topic-cluster-out tests separately. Unseen domain is a harder distribution than unseen prompt; label the difference instead of mixing the scores.

External records need prompt-family, substantive-template-family, date/session and source-version grouping. The schema also records broad output-wrapper IDs for sensitivity checks; a shared generic instruction to write one paragraph does not automatically make every topic one duplicate group. Hold out whole collection batches or interfaces to expose chat-harness shortcuts. Never use a source-specific collector/template assignment as though it were intrinsic model style. Do not use public-leaderboard feedback to choose prompt content or many class-specific thresholds.

### F3. Metric, uncertainty and diagnostics

Official metric: BA = (1/18) * sum over classes of correct_predictions_in_class / number_of_examples_in_class. Compute this explicitly. Ordinary accuracy is very similar on the original balanced corpus but can differ on the hidden distribution. Macro-F1, log loss and calibration are secondary diagnostics, not selection substitutes. [R01]

For uncertainty, resample whole prompt groups with replacement, retaining all their rows, and compute paired BA differences for candidates on the same resample. A 2,000-draw prompt-cluster bootstrap is a reasonable default. Do not treat rows from one prompt as independent or count repeated folds as independent experiments. The interval conditions on fitted models and does not fully represent training or repeated-selection uncertainty; report seed sensitivity separately.

Report eighteen class recalls, a row-normalized confusion matrix, source-family errors, within-family confusion, and an explicitly labeled oracle-family diagnostic if useful. Family diagnostics must state whether they weight six families equally or preserve the official eighteen-class weighting. Report length slices (<70, 70-129, 130-199, >=200 whitespace words), inferred domain/genre slices, raw versus normalized views, and at least one interface/time holdout when external data are used. Sparse slices require counts and cautious interpretation.

Use a positive paired difference, stability across the two development partitions, and acceptable worst-class behavior to justify promotion. A conservative final gate is a lower 95% paired-bootstrap bound above zero; a smaller uncertain gain can remain a candidate, but cannot be described as established. Do not reject a useful complementary model solely because its standalone score is lower: judge its actual nested blend. Predeclare a material-regression tolerance, for example 3 percentage points in a sufficiently populated critical slice, as an engineering choice rather than a scientific constant.

### F4. Public leaderboard use

The attachment allows five submissions per day and two final selections. Use a few planned submissions to check notebook correctness and whether a locally robust improvement survives the public distribution. Do not exhaust the limit merely to tune thresholds. Log every change before seeing its leaderboard score. The official public/private mixtures differ, so a small public gain is not decisive. There is no authority to hand-label, manually identify, or externally query hidden records. [R01, R03]

Budget accounting matters. For H hyperparameter configurations, full five-outer/three-inner evaluation requires approximately 15H+5 model fits, not five. A fixed M-model ensemble with nested inner predictions and outer refits is roughly 20M fits before extra tuning. Cache frozen representations and use bounded screening before that expense. Every expensive direction receives a time-boxed feasibility run before a full fold sweep. For major alternatives, distinguish reproduction failure, resource failure and statistically unconvincing gains.

## H. L40S training and offline Kaggle inference

### H1. Hardware and expected scale

NVIDIA documents 48 GB memory and BF16 support for L40S. It is suitable for full fine-tuning compact encoders and LoRA/QLoRA experiments with modest open LMs. The actual submission accelerator, RAM, VRAM and installed software were not established by the supplied files. Do not infer that Kaggle will provide an L40S, or that two small GPUs automatically act like one larger memory space. [R26]

| Method | Estimated L40S training memory | Estimated time per original-data fold | Approximate weight storage | Offline implication |
| Sparse linear / style | CPU RAM depends on vocabulary | Seconds to minutes; CPU | Often MB to hundreds of MB | Cheap baseline/fallback |
| 150M-400M encoder | About 8-30 GB with tuned batch/length | About 0.25-2 GPU-hours | About 0.3-0.8 GB BF16 weights | Several sequential checkpoints plausible |
| Frozen 0.6B-8B feature extractor | About 3-24+ GB by size/precision/batch | Feature pass about 0.2-3 hours; CPU heads | About 1.2-16 GB BF16 or smaller quantized | Load once per branch; cache features |
| 7B-8B LoRA/QLoRA classifier | About 12-40 GB, configuration-dependent | About 2-10 hours, resumable | About 4-6 GB 4-bit base, or 14-16 GB BF16, plus adapters | Quantization/precision requires validation |
| Source-conditioned 7B | About 20-44+ GB with careful batching | About 3-15+ hours, strongly implementation-dependent | One base plus source adapters | Eighteen forward score conditions per passage |

These ranges are estimates, deliberately broad and not L40S benchmarks. They include likely overhead but not guaranteed fit. Actual sequence length, optimizer states, kernels and data size can dominate. At 400M parameters, BF16 weights alone are roughly 0.8 GB; training memory is much larger because of optimizer, gradients and activations. Do not read the weight-size column as peak VRAM.

### H2. Five-hour job cap and reproducibility

Treat five hours as a process boundary, not an experiment boundary. Save periodic checkpoints containing weights/adapters, optimizer, scheduler, random states, sampler position, epoch/global step, gradient-scaler state where applicable, label mapping, source revision and data/fold hashes. Checkpoint at optimizer-step boundaries. Write atomically and resume with the same total-step schedule instead of restarting warmup. Reserve time to checkpoint and exit around 4 hours 40 minutes; shorten the interval if checkpoint writing is slow.

A future 100-200-step timing/memory pilot should measure peak allocation, tokens/second, examples/second and checkpoint overhead. It is explicitly an implementation-phase task, not something performed during this research. Gradient checkpointing trades compute for memory; use it when it enables a useful batch, not automatically for every small model. Accumulation changes the CE effective batch but not contrastive negatives unless embeddings are retained together.

### H3. Submission implementation

Package all weights, tokenizers, adapter/configuration files, label maps, vectorizers, custom model code and required wheels as permitted notebook inputs before the offline rerun. Pin library versions and checkpoint revisions. New model code such as UltraBERT may require a recent Transformers version or vendored model code; test the bundled environment rather than relying on an online install. Use local_files_only and disable library hub access. [R15]

Read /kaggle/input/competitions/name-that-llm/test.csv dynamically; never assume three rows. Preserve each test ID and the input order. Load one neural checkpoint at a time, use length-aware batches, restore original order after sorting, compute scores without autoregressive explanations, and release GPU memory before the next branch. Select BF16, FP16 or FP32 based on the actual accelerator and validated numerics.

Apply the frozen label mapping and preselected blend, then write /kaggle/working/submission.parquet with exactly id and model, no index. Require one non-null prediction for every unique input ID, no extra IDs, no duplicates, and only the exact eighteen permitted strings. Read the generated Parquet locally to verify its schema and values. This plan creates no submission now. [R01-R02]

### H4. Throughput and ensemble accounting

The measured mean of 145 o200k probe tokens gives a rough workload of 4,000*145*18 = 10.44 million token-condition scores for one eighteen-condition generative model. Five such fold models multiply that to about 52.2 million. This is illustrative arithmetic: the deployed tokenizer, padding and context-loss implementation can increase it. A shared frozen base reduces storage, not the number of conditioned computations.

For compact encoders, a planning throughput of 20-100 passages/second would process 4,000 passages in approximately 40-200 seconds per checkpoint, before loading and preprocessing. This is a target scenario, not an observed rate. At only one passage/second, a single pass already takes about 67 minutes. Therefore deployment feasibility must be measured on the actual Kaggle hardware with the exact artifact, precision and full blend.

Use wall_time = setup + preprocessing + sum(model_load + pass_time) + blending + Parquet_write. Time a representative length-stratified local validation workload and a larger replay workload of training passages, then allow substantial margin below nine hours; six hours is a conservative design target, not an official limit. The hidden size is approximate, so avoid a plan that only barely fits 4,000 rows. A validated encoder/lexical fallback should be prepared before experimenting with heavy generative ensembles.
